## 二、改动 1：修复 iOS 编译断裂（v55）

### 位置

`jni/language_module.cpp:1699-1700`（基线 `91c053c` 中的行号）

### 现象

安卓 1119 交付的代码在 iOS 上**编译失败**：

```
jni/language_module.cpp:1680:17: error: use of undeclared identifier
'lzt_android_log_override_stats'
```

### 原因

安卓侧在 `LangMgr` 写入成功后加了一句接管统计输出：

```cpp
lzt_android_log_override_stats();   // 启动期已过，输出接管统计
```

但该函数定义在 `jni/components/component_patches.cpp`，而**这个文件不在 iOS 的 `SHARED_SRC` 列表里**（见 `iOS/build.sh:36-49`），因此 iOS 根本编不到它的定义。

安卓侧本轮只能做 Android 编译验证，无法执行依赖 `/var/jb/` 的 `build.sh`，所以未能发现。

### 修复

加平台守卫，仅 Android 生效：

```cpp
#if !LZT_PLATFORM_IOS
                lzt_android_log_override_stats();   // 启动期已过，输出接管统计
#endif
```

### 验证

修复后 iOS 编译 0 error。dylib 内 `lzt_android_*` 符号计数为 0，平台隔离正确。

## 三、改动 2：修复 iOS 规则②（v56）

### 位置

- `jni/language_module.cpp:1592-1610` — `start_locale_switch_thread()`
- `jni/language_module.cpp:1930-1960` — `lang_on_main_screen_entered()`

### 现象

删除 `Documents/LanguageFlag` 后启动，游戏语言不生效：语言标识已切换，但**界面文本仍是英文**。

真机日志（v55）：

```
L159  Language flag write: locale=zh-cn result=ok      ← 启动期就写了 Flag
L175  Language switch: wrote 0x454E5553 -> 0x5A48434E  ← 启动期抢跑切换
L178  [SFW] main screen entered (#1)
L193  LangOverride: flag present (zh-cn), rule1 already handled   ← 规则① 短路
```

`rule2` / `rule3` 计数均为 **0**，规则② 从未执行。

### 原因（两个叠加）

**原因 A：启动线程抢先把 Flag 写了**

`start_locale_switch_thread()` 在 Flag 缺失、但能读到 game-config 时，会立即写 Flag 并抢跑切换。等进主界面时 Flag 已存在，规则② 的触发条件（Flag 缺失）不再成立，被规则① 短路。

**原因 B：启动期那次切换只写了 4 字节，没有换表**

启动线程只写了 `LangMgr + LANGMGR_LOCALE_ID` 的 4 个字节，**没有调用** `language_load_lawnstrings()` / `hot_reload()` / `refresh_all_localized()`。文本表根本没重建，所以「标识变了但文字没变」。

### 修复

**修复 A** — 启动期在 iOS 上不再写 Flag、不再抢跑，只记日志后返回：

```cpp
if (configReady && read_config_locale(locale, sizeof(locale))) {
#if LZT_PLATFORM_IOS
    // 启动期只记录，交给主界面规则② 处理
    lzt_core::log_write("Language startup: source=game-config locale=%s "
                        "[deferred to main-screen rule2]", locale);
    return;
#else
    ...原 Android 逻辑不变（写 Flag + set_flag_fourcc + 抢跑）...
#endif
}
```

**修复 B** — 规则② 切换完成后补写 Flag，让下次启动走规则①、不重复切换：

```cpp
lzt_ios_apply_user_config_later(want);   // 完整换表链
write_flag_locale(cfgLocale);            // 落地
lzt_core::log_write("LangOverride: rule2 flag written locale=%s", cfgLocale);
```

### 为什么只改 iOS

Android 的 FourCC 接管（`component_patches.cpp:423` 读 `g_langReady`）依赖启动期 `lzt_android_mark_lang_ready()`。移除会让 Android 失去启动期接管能力，破坏安卓侧已修好的问题 3（重启变回英文）。

因此上述两处都加了 `#if LZT_PLATFORM_IOS`，Android 路径保持原样。

### 修复后行为

| 场景 | 行为 |
|---|---|
| Flag 存在 | 启动期规则① 接管，主界面无动作 |
| 无 Flag + 有配置 | 启动期放行不干预；进主界面后规则② 完整换表 + 写 Flag |
| 无 Flag + 无配置 | 规则③，全程不干预 |

### 验证

两份真机日志均通过，完整链路：

```
Language startup: source=game-config locale=zh-cn [deferred to main-screen rule2]
[SFW] main screen entered (#1)
LangOverride: rule2 config locale=zh-cn -> 0x5A48434E
LangOverride: no flag, apply user config 0x5A48434E (current 0x454E5553)
Lang force runtime switch: begin locale=zh-cn
LRPKG P04 READ packages\LawnStrings-zh-cn.rton bytes=954969
LawnStrings: parsed 12203 entries
LawnStrings: loaded 12203 entries (zh-cn, source=package-rsb)
Lang hot_reload: 0x454E5553 -> 0x5A48434E (zh-cn)
Lang force runtime switch: end locale=zh-cn refreshed=1
Language flag write: locale=zh-cn result=ok
LangOverride: rule2 flag written locale=zh-cn
apply-localized: end
banner refreshed / mainmenu refreshed
```

关键判据：

- `[deferred to main-screen rule2]` 出现 → 启动期确实放手了
- `current 0x454E5553` → 游戏启动时仍是英文，证明启动期未干预
- `parsed 12203 entries` → 真正换了表，不是只写 4 字节
- `banner refreshed` / `mainmenu refreshed` → UI 文本确实回填

## 四、接手须知（重要，避免重复踩坑）

### 4.1 `refreshed=1` 不是文本条目数

`refresh_all_localized()` 在 iOS 下固定 `return 1`（`jni/settings/settings_framework.cpp:923`），语义是「已调度到主队列」。实际回填由 `lzt_ios_schedule_lang_apply()` 异步完成。

判断刷新是否成功，看 `apply-localized` 与 `banner refreshed` / `mainmenu refreshed`，**不要用 refreshed 数值判断**。

### 4.2 `used` 19 与 20 都是正常值

`[STATIC-ONLY] static sites used=N` 的 N 会随用户操作变化：

- 没进设置页：19
- 进了设置页并切换语言：20（多注册 `+0x736d20`）

判断标准：`used` 明显偏离 19~20（如降到个位数）才是异常。

### 4.3 打包必须给 daveconv 执行权限

`pack.sh` 找的是 `$D/tools/daveconv`。如果只编译到 `iOS/build/`，需要复制到 `iOS/tools/` **并 `chmod +x`**，否则报「未找到 daveconv」（这个坑踩过两次）。

### 4.4 manifest 不在交付包里

`pack.sh` 需要 `mFinal.txt`（22 站点清单），位置 `iOS/backup/v52_scanfixed/mFinal.txt`。安卓交付的压缩包不含 `iOS/backup/`，需要从设备原项目复制。

### 4.5 打包命令

```bash
export PATH=/var/jb/usr/bin:/var/jb/usr/lib/llvm-16/bin:$PATH
SDK=/var/jb/usr/share/SDKs/iPhoneOS.sdk
R=/var/mobile/Documents/SCodeProjects/PvZ2-lzt-settings-framework

# 先用编译工具（三个都要）
for t in lztgate daveconv ldcmd_add; do
    clang -isysroot $SDK -arch arm64 -O1 -o $R/iOS/tools/$t $R/iOS/tools/$t.c
    chmod +x $R/iOS/tools/$t
done

# 编译 dylib（静态模式必须带 LZT_STATIC_ONLY=1）
cd $R/iOS && LZT_STATIC_ONLY=1 sh build.sh

# 打包
cd /tmp && OUTNAME=xxx.ipa \
  MANIFEST=$R/iOS/backup/v52_scanfixed/mFinal.txt \
  TNAME=buildN sh $R/iOS/tools/pack.sh
```

### 4.6 静态模式不能漏

`build.sh:31`：`[ -n "$LZT_STATIC_ONLY" ] && CFLAGS="$CFLAGS -DLZT_STATIC_ONLY"`

漏掉这个变量会导致 dylib 走运行时 inline hook，与包内 22 个静态 gate 桩叠加 → 无限循环 → 卡死 EA 图标（v50 事故，勿重演）。

判断方法：打包日志应出现 `模式: 【静态】`；装机日志应出现 `[STATIC-ONLY] static sites used=19`，且 `inline hook` 残留为 0。

### 4.7 平台差异：iOS 与 Android 的 FourCC 接管时机不同

| | iOS | Android |
|---|---|---|
| 接管点 | `0x1AC6D50`（FourCC → 表名） | `sub_16A8A4C` |
| 启动期 | 只读 Flag，缺失则放行 | 读配置后立即 `set_flag_fourcc` 接管 |
| 生效时机 | 进主界面后规则② 完整换表 | 启动早期，首次读表即目标语言 |
| 配置读取 | 依赖 `lang_table_ensure()`（需语言表就绪） | 直接读 `persistManager` |

**注意**：iOS 的 hook 机制与 Android 完全同构（`g_flagFourcc` / `g_langReady` / 规则①②③ 逐条对应），差异只在于 **iOS 启动早期拿不到配置语言**——`read_config_locale()` 依赖语言表，而启动早期表必然为空。

这是平台差异，不是实现缺陷。若未来想让 iOS 也做到「启动即目标语言」，需要绕开 `lang_table_ensure()` 另写配置读取，或承担提前加载资源的竞态风险。

## 六、已知遗留项

1. **规则③ 未在真机触发过** — 日志措辞已带诊断字段 `(langs=N ready=N)`，可区分「确实没配置」与「表未就绪」，但尚无实际场景验证。

2. **`+0x736d20` 站点不在 manifest** — 设置页相关，运行期按需注册。不影响功能，但 `used` 计数会因此变化（见 4.2）。

3. **LiveContainer 下语言表为空** — v54 时期发现的问题：No_Backup 三站点（`0x1c310e8`/`0x1c32040`/`0x1c36564`）不在 manifest，静态模式跳过；越狱直装有符号链接兜底，LiveContainer 的嵌套容器路径导致兜底失败，找不到 `CDN.2.0`。**v56 未处理此问题**。若需要修复，要把这三个站点加入 manifest（22→25 站），gate 区从 1072 扩到 1216 字节（`0x6BD0` 起点仍有余量），但需先验证三站首指令是否 PC 相对（`lztgate` 会 REFUSE）。

4. **iOS 与 Android 语言生效时机不同** — 见 4.7。当前方案已验证可用，未做统一。

### 8.4 首次接入踩到的两个坑

**坑 1：`git fetch` 取不到 `sync/android-baseline`**

本地仓库的 remote refspec 只配置了 `main`，`git fetch origin` 不会带回新分支（`git branch -r` 看不到），但 `git ls-remote --heads origin` 能看到它存在。

解决：显式指定分支

```bash
git fetch origin sync/android-baseline:refs/remotes/origin/sync/android-baseline
```

**坑 2：切分支被未跟踪的 `iOS/` 阻挡**

基线分支包含 `iOS/` 的 31 个文件，而本地 `iOS/` 未跟踪，`git checkout` 报「以下未跟踪的工作区文件将被覆盖」。

解决（已验证安全）：本地 `iOS/` 与基线**逐字节一致**，所以

```bash
mv iOS /tmp/iOS_hold
git checkout -b sync/android-baseline origin/sync/android-baseline
cp -an /tmp/iOS_hold/docs/LawnStrings-en-us.json iOS/docs/
cp -an /tmp/iOS_hold/entitlements.plist iOS/
cp -an /tmp/iOS_hold/tools/{lztgate,daveconv,ldcmd_add} iOS/tools/
cp -an /tmp/iOS_hold/backup iOS/
```

`backup/` 与那 5 个文件本就是 `.gitignore` 排除项，切分支后需要手动放回。

**注意**：`cp -an` 不会复制「原本不在目标目录里」的单个文件时按预期工作——交接文档这类新增文件建议单独 `cp` 确认。
