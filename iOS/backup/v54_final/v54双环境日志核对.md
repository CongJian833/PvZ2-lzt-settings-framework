## 三、唯一差异：语言表加载

| 项 | LiveContainer | 企业签名 |
|---|---|---|
| `LangTable[N]` 明细行 | **0 条** | **16 条**（8 语言 × 2 次） |
| 语言表来源 | `main-screen load force=1 -> unavailable (langs=0)` | `source=cdn-json languages=8 enabled=8` |
| `no_backup redirect` | **hook A=FAIL / hook B=FAIL** | 符号链接创建成功 |
| `LRCDN cdn dir` | **0 条** | 2 条，指向 `No_Backup/CDN.2.0` |

### 成因

企业签名环境下：

```text
no_backup redirect: .../Library/Application Support/No_Backup
                 -> .../Documents/No_Backup (symbolic link)
LRCDN cdn dir: .../Documents/No_Backup/CDN.2.0
LangTable: source=cdn-json languages=8 enabled=8
```

LiveContainer 环境下：

```text
no_backup redirect: hook A=FAIL
no_backup redirect: hook B=FAIL
no_backup migrate(A): AppSupGetter(0x1c36564)->DocGetter: FAIL
（无 LRCDN cdn dir 行）
（LangTable: main-screen load force=1 -> unavailable (langs=0)）
```

**根因**：No_Backup 的三个 hook 站点（`0x1c310e8`、`0x1c32040`、`0x1c36564`）不在 manifest 的 22 个站点中，因此在静态模式下被跳过（正是日志中 7 个 `hook SKIPPED` 里的 3 个）。

越狱直装时，这三个 hook 虽然也 skipped，但**符号链接兜底路径成功**（日志有 `no_backup redirect ... symbolic link`），所以 CDN 目录仍能被找到。

LiveContainer 下容器路径结构变为：

```text
.../Documents/Data/Application/<内层UUID>/Documents/No_Backup
```

多了一层嵌套，兜底路径创建失败，游戏找不到 `CDN.2.0` 目录，语言表加载为空。

### 影响面

- **不影响静态 hook 机制**：22 个 gate 站点全部完好（`all 22 sites OK`）。
- **不影响设置 Tab、视角、戴夫动画、传送带、60fps**：这些均正常。
- **影响**：LiveContainer 下语言表为空，语言切换功能可能不可用（取决于是否有其他加载路径）。

用户报告"功能大概都没有问题"，与此判断一致——语言功能在 LiveContainer 下可能是降级状态，其他功能正常。

## 六、结论

### 已验证通过

1. **静态 gate 双环境完全正常**：`all 22 sites OK`、`blocked code-page writes=0`、`inline hook=0`。
2. **gate 相对偏移恒定 `0x6BD0`**：不受 `ncmds` 81/79 差异影响，v50 根因修复彻底。
3. **设置 Tab 正常**：两环境均 finalize id 30/31。
4. **视角、静态补丁、60fps 全部正常**：逐项一致。
5. **无崩溃、无补丁重装风暴**：`NATIVE_CRASH=0`、`REHOOK=0`。

### 需要说明的差异

**LiveContainer 下语言表加载为 0 种语言**，原因是 No_Backup 符号链接兜底在该容器路径结构下失败，与 gate 机制无关。

若要修复，需要把 `1c310e8`/`1c32040`/`1c36564` 加入 manifest 并重新打桩。但这三个站点此前被判定为"非必要"，现在看需要在容器环境下重新评估。

### 建议

1. **v54 可作为正式版发布**——核心机制在双环境验证通过。
2. **LiveContainer 的语言功能**需单独确认：如果用户在该环境下需要切换语言，应把 No_Backup 三站点迁入 manifest。这需要：
   - 把 `1c310e8`、`1c32040`、`1c36564` 加入 `mFinal.txt`（从 22 站扩到 25 站）
   - 重新打包，确认 gate 容量足够（当前 `cap=22 used=22`，需要扩到 25）
   - 注意 gate 区需从 1,072 字节扩到 1,216 字节，`0x6BD0` 起点不变仍有余量（18,600 → 18,456）
