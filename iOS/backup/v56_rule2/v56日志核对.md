## 二、规则② 执行链路（两份日志一致）

### 2.1 启动期正确放手

```text
Language startup: source=game-config locale=zh-cn [deferred to main-screen rule2]
```

关键标识 `[deferred to main-screen rule2]` 出现，说明启动线程读到配置后**没有写 Flag、没有抢跑切换**，直接返回。这正是 v56 修复的核心。

对比 v55 及更早的日志：

```text
（旧）Language startup: source=game-config locale=zh-cn
（旧）Language flag write: ... locale=zh-cn result=ok     ← 启动期就写了
（旧）Language switch: wrote 0x454E5553 -> 0x5A48434E     ← 启动期抢跑
```

### 2.2 主界面触发规则②

```text
[SFW] main screen entered (#1), notifying 1 handler(s)
LangOverride: rule2 config locale=zh-cn -> 0x5A48434E
LangOverride: no flag, apply user config 0x5A48434E (current 0x454E5553) by reusing reload chain
LangOverride: request switch fourcc=0x5A48434E -> locale=zh-cn
```

`current 0x454E5553` = 游戏启动时仍是英文（EN-US），说明启动期确实没有干预。

### 2.3 完整换表（不是只写 4 字节）

```text
Lang force runtime switch: begin locale=zh-cn
LRPKG P04 READ name=packages\LawnStrings-zh-cn.rton bytes=954969
LawnStrings: parsed 12203 entries
LawnStrings: loaded 12203 entries (zh-cn, source=package-rsb)
Lang hot_reload: locale 0x454E5553 -> 0x5A48434E (zh-cn)
cdn manifest target locale = zh-cn
Lang force runtime switch: end locale=zh-cn refreshed=1
```

这是 v56 的另一半修复：**真正调用了 `language_load_lawnstrings` + `hot_reload`**，解析并加载 12,203 条文本条目（来源 `package-rsb`，954,969 字节的 `LawnStrings-zh-cn.rton`）。

旧版启动线程只写了 `LangMgr + LANGMGR_LOCALE_ID` 的 4 字节，从未加载这张表——这就是「FourCC 改了但文本没变」的直接原因。

### 2.4 控件回填

```text
apply-localized: begin
apply-localized: end ret=0x16bcfa0b8
banner refreshed a1=0x165129dd0
mainmenu refreshed a1=0x165129ca0
```

`banner refreshed` 与 `mainmenu refreshed` 证明已显示的 UI 文本确实被回填。

> 说明：`refreshed=1` 不是文本条目数。iOS 侧 `refresh_all_localized()` 固定返回 1（`settings_framework.cpp:929`），表示「已调度」；实际回填由 `lzt_ios_schedule_lang_apply` 异步完成，成功与否看后续 `apply-localized` 与 `* refreshed` 行。

### 2.5 Flag 落地

```text
Language flag write: ... locale=zh-cn result=ok
LangOverride: rule2 flag written locale=zh-cn
```

切换完成后补写 Flag。下次启动将命中规则①，不再重复切换。

### `used` 19 vs 20 的差异说明

第二份日志在 L132 多出一条：

```text
[ERROR] hook SKIPPED, no static site @+0x736d20 -> feature disabled
```

`0x736d20` 是设置页相关站点，**只在用户实际打开设置页并切换语言时才被触发注册**。第一份日志没有手动操作设置页，所以该站点从未被请求，`used` 停在 19。

这不是缺陷，是运行时条件差异。判断标准仍是：`used` 不应明显偏离 19~20（降到个位数才是异常）。

## 七、v56 改动摘要

**改动 1** — `start_locale_switch_thread()`，Flag 缺失 + 配置存在时，iOS 分支只记日志后 `return`：

```cpp
#if LZT_PLATFORM_IOS
    lzt_core::log_write("Language startup: source=game-config locale=%s "
                        "[deferred to main-screen rule2]", locale);
    return;
#else
    ...原 Android 逻辑（写 Flag + set_flag_fourcc + 抢跑）不变...
#endif
```

**改动 2** — 规则② 切换后补写 Flag：

```cpp
lzt_ios_apply_user_config_later(want);
write_flag_locale(cfgLocale);
```

仅改 iOS 分支：Android 的 FourCC 接管（`component_patches.cpp:423`）依赖启动期 `lzt_android_mark_lang_ready()`，不能移除。
