# 双端代码同步流程（Android / iOS）

> 建立时间：2026-11-19（2026-11-21 双端合并为单一基线）
> 仓库：`https://github.com/CongJian833/PvZ2-lzt-settings-framework`
> 分支：`baseline`（唯一工作分支，Android + iOS 共用）
> 基线提交：`b7fdfbd`
> 目的：替代 zip 来回传输，把同步成本从「人工比对」降到「一条命令」

---

## 一、为什么改用 git

旧方式的问题：

- 每次用 zip 全量传输，实际只需同步共享区
- 靠人工判断「对方改了哪里」，容易漏
- 冲突时没有工具辅助，只能整份覆盖
- 无法回溯「上一版能工作的是什么样」

改用 git 后：

| 旧问题 | git 的解法 |
|---|---|
| 来回传 zip | `git push` / `git pull` |
| 不知道对方改了啥 | `git diff` 精确到行 |
| 冲突 | 自动合并；真冲突才提示，且只标冲突段 |
| 回滚 | `git checkout <commit>` |
| 忘记谁改了什么 | 每次提交带说明，`git log` 可查 |

### 3.4 比对差异

此时 `git status` 会显示你本地与基线的差异：

```bash

```

**重点看 `jni/` 下共享区的文件**（第二节 2.1 列表）。如果差异是你改的、但不该丢的，提交它们：

```bash

git commit -m "iOS: <说明改了什么>"
```

如果差异来自「你手上的版本比基线旧」，用 `git checkout -- <file>` 丢弃本地版。

## 四、日常同步（接入之后）

### 4.1 拉取对方的改动

```bash
cd /var/mobile/Documents/SCodeProjects/repo-sync
git pull
```

看改了什么：

```bash
git log --oneline -5              # 最近的提交
git diff HEAD@{1} --stat          # 本次 pull 带来的文件
git diff HEAD@{1} -- jni/         # 只看共享区
```

### 4.2 推送自己的改动

```bash
git add -A
git commit -m "iOS: <说明>"
git push
```

**提交粒度建议：一个功能/一个修复一次提交**，不要攒一堆再推。这样冲突范围小、回滚也精确。

### 4.3 避免冲突的约定

| 约定 | 原因 |
|---|---|
| 改共享区前先 `git pull` | 减少基于旧代码修改的概率 |
| 只 `git add` 自己改的文件 | 避免误提交对方的半成品 |
| 平台专属代码用 `#if` 隔离 | 已建立的惯例，见第五节 |
| 不提交编译产物 | `.gitignore` 已排除，别用 `-f` 强加 |

## 五、平台差异必须用 `#if` 隔离

这是本仓库的铁律。原因：共享区文件两边都编译，任何一处「只对一端有效」的代码都会让另一端编译失败。

### 5.1 已发生的两次事故

**事故 1（Android 侧造成）**

Android 在 `language_module.cpp` 加了：

```cpp
lzt_android_log_override_stats();
```

该函数定义在 `components/component_patches.cpp`，**不在 iOS 的 SHARED_SRC 里**。iOS 编译报：

```
error: use of undeclared identifier 'lzt_android_log_override_stats'
```

**事故 2（iOS 侧造成）**

iOS 改规则② 时若直接删掉启动期接管，会让 Android 的 FourCC 接管失效（依赖 `lzt_android_mark_lang_ready()`）。

### 5.2 正确写法

```cpp
#if LZT_PLATFORM_IOS
    // iOS 专属逻辑
#else
    // Android 逻辑（含 ARM32 时再套一层 #if defined(__aarch64__)）
#endif
```

平台宏来源：

- iOS：`iOS/include/offsets_ios.h` 定义 `LZT_PLATFORM_IOS 1`
- Android：`jni/offsets.h` 的 `#else` 分支定义 `LZT_PLATFORM_IOS 0`

注意 Android 的 `offsets.h` 用的是 `#if defined(__APPLE__)` 判断，iOS 构建靠 `__APPLE__` 走分支——**不要依赖 `-D` 传宏**，会被头文件里的定义覆盖。

### 5.3 提交前自检

Android 侧有一个专门的测试：

```bash
python tests/test_ios_platform_guards.py
```

它会解析 `#if` 嵌套栈，检查每个 `lzt_android_*` 调用在 iOS 构建时是否参与编译。参与即报错并给出文件行号。

**建议 iOS 侧也加一个对称的**：检查 `lzt_ios_*` 调用在 Android 构建（`LZT_PLATFORM_IOS=0`）时不被编译。可以直接改这个脚本的 `MACROS` 常量复用。

## 六、仓库内容说明

### 6.1 跟踪了什么

```
jni/                 全部源码（含 Android 专属）
iOS/                 源码、垫片、工具 .c、文档
tests/               静态测试（6 个）
dist/                四个 .so（debug/release × 两个 ABI）
docs/                偏移量指南、语言表样例
文档/                （在仓库外，见 §6.3）
.github/             issue 模板
build_variants.py    双变体构建脚本
feature_flags.conf   功能开关
```

### 6.2 明确排除什么

| 排除项 | 原因 |
|---|---|
| `jni/libs/`、`jni/obj/`、`iOS/build/` | 编译产物，可再生成 |
| `iOS/backup/` | 本地版本归档，体积大 |
| `iOS/tools/daveconv` 等 7 个二进制 | 有对应 `.c` 源码 |
| `tests/.pre-*` | 本地回归基线，不该进历史 |
| `*.bak`、`*.apk`、`*.ipa`、`*.so.bak` | 备份与成品 |
| `libPVZ2.so`、`*.i64`、`*.idb` | 游戏原文件，版权敏感 |
| `*.jks`、`*.keystore`、`*.mobileprovision` | 签名材料 |

**不要用 `git add -f` 强行加入这些。** 体积和版权问题都会带来麻烦。

### 6.3 文档不在仓库内

Android 侧的 `文档/` 目录在仓库**外面**（`workspace-lzt/文档/`）。原因是它包含 iOS 文档、分析报告等，不属于这个代码仓库。

需要共享的文档，直接放进 `iOS/docs/` 或 `docs/`，就会纳入版本控制。

## 七、出问题怎么办

### 7.1 冲突

```bash
git pull
# 提示 conflict，编辑冲突文件，保留正确内容后：
git add <冲突文件>
git commit
```

冲突标记长这样，保留正确的那段、删掉 `<<<<<<<` 等标记：

```cpp
<<<<<<< HEAD
    // 你的版本
=======
    // 对方版本
>>>>>>> origin/baseline
```

拿不准就**停下来问**，不要硬合。

### 7.2 改错了想回退

```bash
git log --oneline -10               # 找到想回到的提交
git checkout <commit> -- <file>     # 只回退某个文件
```

整体回退（谨慎，会丢未提交改动）：

```bash
git reset --hard <commit>
```

### 7.3 想看某个文件的历史

```bash
git log --oneline -- jni/language_module.cpp
git diff <commit1> <commit2> -- jni/language_module.cpp
```

## 八、关于旧的 zip 流程

本仓库建立后，**zip 只用于成品交付**（IPA / APK），不再用于源码同步。

Android 侧仍保留 `归档/` 机制（`python Tools/archive_snapshot.py`），用于冻结「已验证可用的完整状态」，与 git 的日常同步是两回事：

| | git | 归档 |
|---|---|---|
| 频率 | 每次改动 | 每轮真机验证通过后 |
| 内容 | 源码与产物 | 源码 + 文档 + 环境快照 |
| 用途 | 协作 | 冻结可用状态、回溯 |
